# SupportPilot

A multi-tenant AI support agent built on Onyx. It helps authorized support staff find customer,
order, shipment, and ticket information, summarize support history, and request controlled business
actions — using real services, a persistent PostgreSQL database, individual user identities,
policy-based authorization, approval workflows, and audit records.

> **Core rule:** the model may propose tool use, but trusted services decide what is allowed and
> perform every real action.

## Architecture in one paragraph

Onyx runs the agent loop and calls registered OpenAPI actions, forwarding the individual user's
OAuth token. The SupportPilot API verifies the token against Keycloak, loads trusted resource
attributes from PostgreSQL, asks OPA for a decision, then queries under a restricted database role
with row-level security and transaction-local tenant context. Sensitive actions never execute in the
request path: the API records an immutable payload hash, an independent approver approves it, and a
separate worker executes it once through an allowlisted adapter.

## Quick start (once phase 0 exists)

```bash
./scripts/bootstrap-local.ps1
./scripts/verify-local.ps1
```

`verify-local.ps1` prints one pass/fail line per check `V-01`–`V-12`
([docs/08-local-build-runbook.md](docs/08-local-build-runbook.md#12-step-10-end-to-end-verification)).
Every line must pass before a phase is considered complete.

## Non-goals for the first release

Autonomous refunds without approval · free-form SQL generated by the model · general shell,
file-system, or cloud-administration access · training or fine-tuning a model · replacing the
existing support system of record before integrations are proven.
